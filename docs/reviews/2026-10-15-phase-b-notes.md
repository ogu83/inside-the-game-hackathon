# Phase B notes: proposals for SPEC.md (not applied)

Cloud session, 2026-10-15, while building T3 to T12. **All four approved by Oguz on 2026-10-15 and applied to SPEC.md the same day** (status line, design rules 2 and 3, capability map, testing strategy).

1. **Producer coverage rule (T8).** The planted error "dropped number" cannot be caught by a number check alone, because a text with fewer numbers is not wrong. The producer gate therefore also compares the rendering with its verified source: with coverage `all` (analyst depth and the overlay metric) every number in the source claim must survive; with coverage `any` (casual depth) at least one must survive when the source has numbers. A failure is recorded as `dropped number: 14` in the `NumberCheck`. Proposal: add this sentence to design rule 2 under gate (b). Implemented in `check_rendering` (app/agents/fact_check_rules.py).
2. **Swapped team is a layer 2 catch.** A planted "swapped team" keeps every number right, so layer 1 passes it by design and only the wording judge can reject it. The offline harness reports it as reached air; the live harness (`pytest -m live`, `run_match --plant 4 --live`) must bring it to 0. Proposal: say in the testing strategy that the planted-error target of 0 applies to the live run, and that the offline run proves the code layer alone catches every number error.
3. **`PacingState` (T7).** The director receives a code-computed `PacingState` (seconds since the last cue, cues and moments in the last 2 minutes, rank among recent moments, interest score). It is an internal contract between code and the Analyst, not a cross-module payload, so it is not in the Interfaces section. Proposal: mention it in design rule 3 by name.
4. **Player distance is a proxy (T5).** Event data has no tracking, so `player_distance_m` sums the metres between a player's consecutive event positions. Proposal: the capability map's "player speed/distance thresholds" becomes "player involvement and distance proxy"; speed thresholds are not computed.

## Proposals from the live planted run (2026-10-15, later): strengthen design rule 2

Both are implemented in `app/agents/fact_check_rules.py` and tested with the exact live cases; SPEC.md was not edited.

5. **Numbers match the fact they quote (layer 1).** Live case: a tampered rendering "13 pressures from 3 players in 13 seconds" passed because the 13 matched the 13-second window. Proposed wording for rule 2, layer 1: "A number is matched to a cited value of its own kind: the noun after the number (passes, pressures, players, shots, goals, seconds, minutes, metres, percent, and their Turkish forms) names the fact it quotes, and the number must equal a cited key of that fact (`13 pressures` against `pressing_trap_pressures`, not against `pressing_trap_window_s`). A number with no noun may match any cited value. Seconds and minutes cross-match through unit conversion. A number whose fact was not cited at all fails." The mismatch reads `13 pressures does not match the cited pressures value (pressing_trap_pressures = 2)`.
6. **Attribution is checked by code (layer 1).** Live case: "Kestrel Bay set a pressing trap ... and Jory Calloway led the action" passed layer 2 although the moment was Ironvale's. Proposed wording for rule 2, layer 1: "The claim and why-it-matters must attribute the moment to `moment.team_id`: the opponent club and its players may be named only as the ones acted upon (English: after against, past, from, pressed, beat and similar, or as the side chasing, conceding or struggling; Turkish: with a case suffix such as Kestrel Bay'a or followed by karşı, savunmasında and similar). Any other mention of the opponent or of one of its players as the actor is a code-layer rejection with the reason and the correct team. Layer 2 remains the second net for wording." The planted swapped team is now caught by code offline; the live harness keeps the 0-reached-air target.
